# Narwal protocol enums (decoded)

Value→name tables extracted from the decompiled app with `re/tools/dump_enums.py re/build/blutter-out/pp.txt`. Enum member *names* survive in the constant pool even though they were stripped from the pbenum constructors (`_omitEnumNames`).

Caveats:
- Some enums are missing **value 1** (the healthy/normal state): blutter omits constants never directly referenced. e.g. CleanWaterTankState declares 5 but only 0,2,3,4 have emitted names; value 1 = the live healthy value. Every *named* value ≥ 2 is an attention state.
- **Status-broadcast enums don't match runtime on this firmware.** `RobotBaseStatus_ChargingStatus` (field 47) decodes to {0,5} but live=3; `RobotTaskStatus_TaskType` (field 3 sub-1, the working state) decodes 14=WASH_AND_DRY_MOP but live 14=docked/charged. The integration keeps its empirical `WorkingStatus` map + dock/charging heuristic for these two fields — do NOT wire field 3.1 / 47 to these tables. The command/config enums (FanLevel, MopHumidity, CleanMode) and the tank/consumable state enums DO match live (tanks=1=ok), so those are safe.
- Regenerate after `nix run .#disassemble`.
